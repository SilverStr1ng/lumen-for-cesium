## 现在可以操作

`npm run setup` → `npm run build` → `npm start`。打开 [Models](http://localhost:8090/demo/pilot-models.html) 或 [Tiles](http://localhost:8090/demo/pilot-tiles.html)。等待数据/GI available 后切换基础 DDGI / FG Auto、改灯、替换、取消；Tiles 支持父/子级显示。数据就绪独立于当前可见内容，业务可另调用有截止时间的 `waitForVisible()`。

改灯采用一个活动请求加最新待处理请求，各调用有 completed / superseded / cancelled 结局。预算拒绝在分配前发生，旧显示、灯光与世界继续匹配。接触缓存仍仅为显式实验档，承担 R10 的失败。

## 实际画质与成本

原三代表失败点在同方向下做8192样本GPU查询及32768样本独立物理/legacy参考。等价表达一致，门洞点增加采样后仍偏亮；天空与直接太阳不足以解释差值，命中表面的 DDGI 余项是该点的主要偏差。起点策略差异解释部分点，不能解释全部失败。本轮不添加新算法或修改目标参考。

详见[等价与源项候选](../../reports/local-gi-pilot-stabilization-v11/r12-2-equivalence-lod/equivalence.json)。原 R11 34/40 画质失败、R10 18/60 最终像素失败及 R8 固定32r性能失败均保留。

RTX5080 / Ryzen7 9800X3D / Windows11 / Chrome155 / WebGL2，真实1920×1080。阴影2048、曝光1、2m/128r/3轮不变。修正后的活动FG性能候选 GPU P95：Models静止/移动12.85/13.56ms，Tiles15.19/13.67ms；CPU与帧间隔均满足33.3/40ms候选门限。后续增加了disjoint审计，正式结果须重新测量。

R11增强档原5.25/7.88ms窗口是在 FG 停止采样后测得，不能继续称为持续活动性能。该历史数字保留，条件解释更正。新的测量明确限定240帧窗口，不混入预热或查询收尾帧。

64MiB口径包含冻结输入及Blob副本、CPU缓冲、显示/环境、DDGI、快照、FG与查询。短资源确认候选的 Models/Tiles 准入峰值64,244,794 /66,876,532B；不足20替换/50LOD，整体明确标 not-run。逻辑合计不是驱动VRAM；驱动/JS allocator及桌面光子延迟仍为 not-run。[资源合同](../product/local-gi-resource-scope-v11.md)列出范围、限制与独立GL核对。

## 加权账本与阻断

沿用[baseline-v1](readiness/baseline-v1.json)权重、100分分母与五档成熟度锚点；本次采用用户提供的[不可变v10审查](readiness/v10-review.json)，主目标 **48.75≈49%**、受限试点 **63.75≈64%**。仅资产/API及主目标 Tiles 基础加分；其他项不加分。逐项权重、理由与来源保留在原始审查，测试通过率和提交数量不参与评分。

投入使用仍受独立区域画质失败、尚未完成的冻结总验收阻断。下一步先冻结当前实现，执行 `npm run test:r12` 的11个必需关卡；失败返回非零，未运行记 not-run。只有全部公开必需关卡通过才可标 pilotReady。若共同估计仍不能满足质量门限，下一算法只研究有界第二段路径积分替换命中余项，并先证明误差与运行成本；本轮不实现它。
